# CitePilot

持续监测回答引擎会不会提到你、会不会引用你的公开页。产品循环是四步，不是按周打卡。

1. **基线监测**：新建或选中一个轮次，类型标成基线。把题库里的题拿到各回答引擎去问，再把回答粘贴回来。同一道题可以贴多条，每条标一个平台。
2. **整站+内容分发**：诊断公开页，用内容起草写出稿子。发布由你自己完成，这里不代发。
3. **一段时间后再监测**：新建一个轮次，名称用当天日期或「改站后」，用同一套题再测一遍。
4. **与基线对比**：对比页左侧选基线，右侧选后来的监测，看提及率、引用率、声量占比和平均排名有没有变化。概览上有按批次排开的趋势。

一轮见效之后，可以把最近这批当作下一轮的基线：对比时把它放在左侧，或新建时把类型选成基线。

不做多平台一键发布，也不登录去爬 ChatGPT、豆包或其他对话产品。监测只解析你粘贴的文本。种子里的「示例·优化前」和「示例·优化后」是一对历史样本，同一道题有多条、多平台回答，用来演示第 4 步和概览趋势。

## 技术栈

- API：Cloudflare Workers + Hono
- 数据：Cloudflare D1（`migrations/`）
- 前端：React 19 + Vite，由 Workers 静态资源同仓提供
- 界面：Astryx（`@astryxdesign/core`、`@astryxdesign/theme-neutral`、`@stylexjs/stylex`）
- 模型：OpenAI 兼容接口。可以在「设置」里保存多套配置（DeepSeek、OpenAI、通义千问、Kimi、智谱、豆包、OpenRouter 或自定义地址），内容生成和分析可以分开选。没有保存配置时，回退到环境变量 `DEEPSEEK_API_KEY`。密钥写入 D1 后不再回显，只显示末四位。

## 本地运行

需要 Node.js 22+。

```bash
npm install
npm run db:migrate
npm run dev
```

`npm run dev` 会先把迁移应用到本地 D1，再启动 Vite。Vite 插件使用 Wrangler / workerd，页面和 `/api` 在同一个地址，默认是 <http://127.0.0.1:5173>。

打开后会看到种子品牌「澄川智能体工场」、20 道中文题，三家带别名和域名的竞品，以及一对历史样本「示例·优化前」「示例·优化后」。同一道题有多条样本。示例官网是 `https://example.com`，方便直接跑诊断；日常使用时改成你的真实站点。种子品牌也可以删除：在品牌页输入完整名称确认后，题目、批次、样本、诊断和草稿会一起清掉。

## 对照澄川样例

`npm run db:migrate` 会把种子品牌澄川填成一份对照。不会改你另外新建的品牌。澄川自己的素材库会换成这批样例。

1. 打开「品牌」。页面上只有定位、四条服务、三家竞品、关键词，以及语气、禁用词、合规红线。
2. 打开「素材库」。里面有案例、产品、巧思、交互细节、数据成效、踩坑和客户评价。点一条标题，左侧改信息，右侧排版正文。尽调那条是匿名案例，写了客户授权的 45 分钟到 8 分钟。另有一条标成不可公开，起草时不能勾。
3. 打开「内容起草」，勾选两条没有锁住的素材，植入强度保持「不植入」，再生成草稿。

其他命令：

```bash
npm test                 # 解析、声量、题库、诊断、对比的单元测试
npm run typecheck
npm run build            # 类型检查 + 生产构建
npm run preview          # 用 Workers 运行时预览构建结果
npx wrangler dev         # 只跑 Worker。页面开发请用 npm run dev
npm run deploy           # 构建后 wrangler deploy。部署前先换成真实的 D1 id
```

`npm run dev` 已包含 Worker。单独执行 `npx wrangler dev` 时，API 可用；静态页面以 Vite 构建结果为准。

## 配置模型

本地可以只配环境变量，也可以在页面「设置 / 模型配置」里保存多套。页面里的密钥写入本地 D1，接口不再把明文密钥返回给浏览器。环境变量仍然优先作为「没有保存配置」时的回退。

```bash
cp .dev.vars.example .dev.vars
```

`.dev.vars`：

```bash
DEEPSEEK_API_KEY=sk-...
# 可选。下面两项在 wrangler.toml 里已有默认值。
# DEEPSEEK_BASE_URL=https://api.deepseek.com
# DEEPSEEK_MODEL=deepseek-chat
```

也认 `OPENAI_API_KEY`，但 `DEEPSEEK_API_KEY` 优先。`DEEPSEEK_BASE_URL` 默认 `https://api.deepseek.com`，请求发到 `{BASE_URL}/chat/completions`。`DEEPSEEK_MODEL` 默认 `deepseek-chat`。

改完后重启 `npm run dev`。概览页会显示当前用的是保存的配置还是环境变量。设置页可以「测试连接」，并分别指定「内容生成」和「分析 / 抽取」。

有密钥时：

- 「生成题目」优先让模型按品牌资料写新的中文问题，失败或结果不合格则退回模板
- 诊断建议优先让模型根据清单改写，清单本身仍由规则计算
- 监测摘要会让模型用中文解释规则结果，并给本品牌标正、中或负。品牌是否出现、排名、网址和竞品仍以规则为准，避免模型编造引用
- 内容起草从素材库勾选一条或多条，按内容类型合成一篇。默认「不植入」，正文不写品牌名。需要时可选「软植入」或「明确种草」。数字只来自客户授权的前后数据，没有就写成「【待补充】」。

没有密钥时，上面这些都用模板和规则。情感可能是「褒贬都有」，主流程可以完整走通。

线上密钥：

```bash
npx wrangler secret put DEEPSEEK_API_KEY
```

新增迁移：

```bash
npm run db:migrate
```

`0008_llm_and_cascade.sql` 重建样本表的级联删除，并加上模型配置表。`0009_brand_profile.sql` 给品牌加上介绍、语气和红线等可选字段。`0010_assets.sql` 建立素材库，并把当时已有的案例详情和参考资料搬进去。`0011_chengchuan_demo.sql` 给澄川填上品牌页样例，并把澄川的素材库换成对照用的八条素材。已经在跑的本地库执行一次 `npm run db:migrate` 即可，不必删库。

## 循环里的页面

1. **品牌 / 素材库 / 题库**：品牌页只留名称、官网、定位、服务、竞品（名称、别名、域名）、关键词，以及品牌语气、禁用词、合规红线。案例、产品、巧思、交互细节、数据成效、客户评价、踩坑和参考资料进素材库，可以按类型、标签搜索。点一条标题后，左侧是类型、标题、公开程度、标签和已授权数据，右侧是正文。正文可以加标题、加粗、列表、链接和图片。「和 AI 一起打磨成可分享素材」只整理已经写下的句子，不补数字，也不写成硬广。保存后可以「去起草」。数据成效要写指标名、优化前、优化后、单位、口径，以及客户是否授权公开。以前存在品牌上的介绍、能力、案例列表和异议仍留在数据库里，品牌页保存时不再改它们。题库仍覆盖品牌、品类、对比、场景。删除品牌要输入完整名称，题目、批次、样本、诊断、草稿和素材会一起删除。
2. **监测**：选择批次和平台，粘贴回答。同一道题可以贴多条，平台可以选自列表，也可以自己填。每条样本会标出提到哪些追踪品牌、第一次出现的名次、域名有没有被引用。提及率 = 提到本品牌的样本数 / 总样本，引用率同理。声量占比 = 本品牌被提到的次数 / 所有追踪品牌被提到的次数。页面按题、按平台分组，并写明样本量。少于 5 条时提示结论不稳定。旧的一题一答仍算 1 个样本。
3. **诊断**：抓取公开页、`/robots.txt` 和 `/llms.txt`。内网、本机和云元数据地址会被拒绝。
4. **内容起草**：勾选素材库里的一条或多条，选择内容类型、目标读者、语气、长度和植入强度。从素材点「去起草」会带上那一条，并按素材类型选一个内容类型。页头标着「素材 → 起草 → 发布 → 监测」。默认「不植入」，正文不提品牌。软植入仍从素材写故事，只在叙述里放进一两句可引用的事实。缺了客户授权的前后数据时，页面会提示「信息不足」。复制后由你自己发布。
5. **对比**：左侧是基线，右侧是后来的监测。两侧都有样本量、提及率、引用率、声量占比和平均排名。概览按批次画出提及率和声量占比。
6. **设置**：保存多套模型，测试连接，并为内容生成和分析各选一套。

种子数据里，「示例·优化后」的品牌提及率和声量占比都高于「示例·优化前」，平均排名也更靠前。这些记录可以删掉，换成你自己的粘贴。

## 四周自测（可选）

只在第一次验证时用，走完就回到上面的四步循环。工具不代你发内容，发布在你自己的站点完成。

| 周 | 做什么 |
| --- | --- |
| 第 0 周 | 核对品牌资料。确认题库覆盖四个簇。新建一个抽查批次，把同一批题拿到 ChatGPT、DeepSeek、豆包、Kimi 等平台去问，再把回答粘贴回来。 |
| 第 1 周 | 对官网跑诊断。优先补标题、描述、单一 H1、常见问题、Organization 或 FAQ 结构化数据，以及 `/llms.txt`。用「内容起草」挂上一个未通过项，生成 FAQ 或官网长文，先审再决定贴不贴。 |
| 第 2 周 | 把审过的草稿贴回自己的网站，包括官网长文、FAQ 和「产品宣传」。补上可引用的定义、服务边界和案例。 |
| 第 3 周 | 再新建一个抽查批次，抽几条对比题和场景题问一遍，看自有网址有没有开始出现。 |
| 第 4 周 | 把第一次抽查的题补进新批次，打开对比页任选这两批。差距留给下一次改页。 |

概览页把同一份说明收在「四周自测（可选）」里，默认折叠。日常按上面的四步循环，不用按周。

## 内容起草

诊断出缺口后，打开「内容起草」。页头是「素材 → 起草 → 发布 → 监测」：素材在库里写完，这里按渠道起草，发布在站外，监测看回答里有没有被引用。选好内容类型后，会按类型勾上最接近的几条已有素材，也可以改或点「重新推荐」。从素材库「去起草」进来时，那一条会留在勾选里。再确认植入强度。渠道包括官网长文、FAQ页、公众号、小红书、LinkedIn/行业稿、社媒短帖和产品宣传。可以挂一道题库里的题，或一次诊断里未通过的检查项。题目收在「高级」里，默认不写进正文。故事优先，不写硬广，不凑字。

植入强度有三档。不植入：只分享素材，不写品牌名，也不硬加问答。软植入：故事仍从客户的问题或数据写起，最多在结尾出现一次品牌名；若关联了题目，答案写进故事中段，不当标题。明确种草：有意推广时，结尾写出品牌名、官网和下一步。硬广和空话（立即咨询、行业领先、赋能数字化、一眼广告腔）会被标出并改回素材里的事实。

生成结果有标题、正文、建议被引用的句子，以及建议落地网址。有模型密钥时，模型把勾选的素材合成一篇；没有密钥时，用这些素材套模板。没有勾选素材时，页面会提示信息不足。左侧是配置，右侧改标题和正文。核对后保存到草稿箱，再复制到你自己的官网或账号。草稿箱收在右侧「草稿」标题旁，点开后可以打开或删除。打开会把这篇稿载入右侧编辑器。保存会更新原来的记录并记下最后编辑时间。

这一步不登录、不代发，也没有各平台的 OAuth。要上线的句子，由你贴回自己的站点。

## 素材里的图片

素材正文可以插入图片。上传是 `POST /api/studios/:id/media`，读取是 `GET /api/media/<品牌 id>/<文件名>`。正文里的图片地址会留下，并记在这条素材的 `details.images`。

`wrangler.toml` 把 R2 绑定成 `MEDIA`，桶名 `citepilot-media`。本地 `npm run dev` 使用 Wrangler 自己的本地 R2，不用先在 Cloudflare 上建桶。线上第一次部署前：

```bash
npx wrangler r2 bucket create citepilot-media
```

如果运行时没有 `MEDIA` 绑定，Worker 会改写到项目下的 `.data/media/`。这只适合本机兜底，线上请用 R2。单张上限 4MB，只接受 JPEG、PNG、GIF、WebP。

## 部署

`wrangler.toml` 里的 `database_id` 是本地占位。部署前：

```bash
npx wrangler d1 create citepilot
```

把返回的 id 写回 `wrangler.toml` 的 `database_id`，然后：

```bash
npx wrangler d1 migrations apply citepilot --remote
npm run deploy
```

远程迁移会写入种子品牌和示例记录。若生产库不要示例监测，可在部署后于界面删除那些记录，或删除整个种子品牌。也可以只在远程执行 `migrations/0001_init.sql`。之后的迁移请用 `npx wrangler d1 migrations apply citepilot --remote`，不要跳号。
